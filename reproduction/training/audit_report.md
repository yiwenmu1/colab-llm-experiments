## 影响效果确认的关键问题

1. 生成样本重复当前 user；备用掩码缺失/失败时可能回退全提示训练，padding 也未屏蔽。修复已提供原源码补丁，并以显式 prompt/target token 边界实现独立训练入口。
2. 原默认 max_steps=120 会覆盖 epoch 配置；标准 HF 分支没有传入序列长度。补丁显式配置长度字段，正式训练以 -1 使用 epochs。20-step 检查显式指定步数，不能替代正式训练。
3. task1 字符串 bias_tags 直接 join 会逐字分隔。新数据与状态组件先规范化标签。
4. task2 从不含当前发言的历史 context 提取患者句子，中文冒号分支仍用英文冒号 split；成功交互后又给所有样本同一个“低危/轻微”下一状态。原状态流不能作为真实患者状态更新的证据。
5. 读取/嵌入失败用随机或零向量回退，会让坏数据继续进入经验池。新契约对缺失当前发言、缺失下一轮标注、错误维度和非有限向量直接报错。
6. 默认关闭所谓“症状改善”奖励；现有质量项实际评分 skill/coherence，且异常有固定奖励回退。不能将其等同于被测量的真实症状改善。奖励数值、KL 方向和重置协议仍须与论文逐项核对。
7. env_states 只决定并行数量；每步重新 random.choice 状态池，没有沿用更新状态。需确认作者是否有意使用独立单步交互采样，不能直接当作完整多步轨迹实现。
8. task3 存在改写测试集的分支。本次训练入口只读公开 train.json，不执行该分支。

## 真实 GPU 检查设计

从干净 Qwen3-8B 开始，分别做原数据 generation-only 与分类＋生成联合 SFT 各20步。每组重置同一初始 LoRA，固定数据和种子；不加载作者 CoPoLLM adapter。

NF4、BF16 量化层计算、rank16/alpha32/dropout.05、lr2e-4、microbatch1、梯度累积1、GC开启；最大1024 token，回复最长256 token；联合任务1:1交替。

训练样本每任务16条，验证样本每任务16条；额外查看固定8条验证分类输出。数据清单在结果产生前冻结。比较训练信号、有限非零梯度和验证损失，禁止将此小样本结果与此前981条最终测试指标直接比较。

第10步保存并恢复 adapter、optimizer、scheduler 与 RNG，并验证权重和学习率恢复。该检查为同进程还原，不宣称冷启动恢复已验证。

## 仍不能确认的效果

- 20步只能验证管线和短期学习趋势，不能确认泛化提升或论文数值。
- 没有真实模拟交互、稳定状态嵌入和独立奖励/质量评估，就没有 CPRL 策略收益证据。
- 本次未生成自己的 PRO，原数据联合 SFT 不等于 PRO+DSCO。
- 不调用外部教师 API 时可以部署本地替代后端，但必须记录替代条件并另做效能实验，不能视为与论文 GPT-4o 教师条件相同。

下一轮正式确认需要：按对话固定验证集、真实 CPRL 状态与转移、策略增强 PRO、等预算的 generation-only/联合训练对照、最终测试集评测与固定生成样本的独立质量评估。
